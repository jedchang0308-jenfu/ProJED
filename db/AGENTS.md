# DEV-139 ProJED 資料庫邊界

這個目錄只放 ProJED DEV-139 的 Cloud SQL／PostgreSQL app-owned schema 與 forward-only migration。它不是現有 `supabase/migrations/` 的別名，也不能把 Supabase policy、`auth.uid()`、RPC 或歷史 migration 原封搬入。

## 所有權與執行責任

- `projed_owner_disposable` 擁有本 app 的 schema、table、function 與 policy；runtime 不可成為 owner、BYPASSRLS 或取得 owner membership。
- `projed_migrator_disposable` 只在已核實的 DEV-139 disposable 或 managed binding 內執行本目錄的有序 migration；不建立 database、foundation role、Secret 或其他 app 的物件。
- `projed_importer_disposable` 只在 runtime 尚未開放業務寫入的空白 candidate DB 執行一次性、單交易 full-snapshot import／reconciliation；不得執行 DDL、UPDATE、DELETE 或成為 owner／BYPASSRLS，正式 credential 由 foundation／release 邊界另行建立與撤銷。
- `0020` 允許上述受控 importer 一次匯入已有 source Google proof 的 active account guard（revision=1），須先在同一來源快照排除 Auth 已停用／刪除狀態；不擴張 runtime 的 guard 權限，也不按 email 猜配或啟用缺 proof 的帳號。
- `projed_runtime_disposable` 依 app source profile 取得自有 domain 的精確 grants／RLS；不執行 DDL、刪除 profile、修改 guard／metadata 或讀其他 app core；ledger 僅允許 `0029` 的受控取消結算、`0031` 的精確 cleanup proof 與 `0032` 的單次來源預留，不開一般修改權。僅 `0022` 首次登入與 `0023` 已有 Google proof 的 email 同步可依下方條件插入／更新；缺 proof／guard 或 inactive 不自動補建／啟用。身分 current state 只可使用 owner 已授權且版本釘定的 `platform_contract.read_projed_principal_state_v1`；source adapter 不代表正式 grant 或已發布契約。
- `0022` 是 runtime profile／proof／guard INSERT 的窄例外，僅限首次登入建立全新 UUID，且必須在同一交易內綁定未過期、仍為 `processing` 的 login intent claim 與尚無既有 proof 的已驗證 Google subject。column grants 僅允許 profile `(id,email,display_name)`、proof `(google_subject,local_user_id)`、guard `(local_user_id,active,revision)`；RLS 限制 profile id／current actor／email、Google proof 與 active revision 1 guard。註冊 insert 不覆寫既有 profile、proof 或 guard；既有 profile 欄位更新授權維持原狀，且註冊路徑不提供刪除、rebind 或自動啟用既有 guard 的權限。`registration_scope_valid_v1()` 為無參數 `SECURITY INVOKER` helper，先驗證 GUC 文字形狀再於自身 login-token RLS scope 中查 processing intent；各 policy 的讀取方向不得形成 RLS 遞迴。
- `0023` 僅允許 runtime 在既有 email 確實變更時更新 `profiles.email`。同一交易必須綁定仍為 `processing` 且未過期的 login intent claim、已驗證 Google subject 與原 profile UUID，並證明該 Google proof 仍指向該 UUID；不更新 UUID、proof、guard 或其他 profile 欄位。既有 `display_name`／`ui_preferences`／`updated_at` 欄位更新權限維持原狀。`profile_verified_email_update_v1()` 為固定 `search_path` 的 `SECURITY INVOKER` trigger，NULL 或不相符狀態以 `42501` 拒絕；email 無實際變更時不要求註冊 scope。
- `0024` 只允許 server 在 exact `rag_record_id` 且 actor 可寫來源 record 的範圍內維護 `knowledge_records` 文件 mirror、append-only versions 與 chunks；record 的 RAG 啟用限定 published、non-private 且已有 source document。一般文件讀取仍由 `0017` source-record 權限與 pointer 決定。Index job INSERT/worker UPDATE 綁 exact document/job、Google provider、current version/hash 與有效 lease；embedding 寫入限目前 job claim、current chunk/version/hash 及 3072 維 Google model。job supersede 只允許可寫來源下的 pending/running job；`external_rag_objects` 不授 runtime DML。Project LLM access log 只允許有 `read_board` 的 actor 存取／寫入自己的 project row，不擴張 workspace-wide audit 權限。
- `0025` 以 exact `rag_document_id`、啟用文件及有效 actor context 提供 worker row-lock policy；`WITH CHECK (false)` 不新增 document UPDATE 路徑，也不放寬既有 SELECT。job guard 僅在 owner 執行的巢狀 FK trigger 且 row 僅有 tenant cascade 或 `document_version_id` 非空轉 NULL 時略過；runtime 仍無 tenant／provenance 欄位 UPDATE 權限。
- `0026` 保留原會議 capture／segment／pointer／run／transcript／review／projection 及 cleanup／budget／usage 的 11 類資料；僅授一次性 importer SELECT／INSERT，runtime 無直接讀寫。衍生 scope 綁定原 capture／record／Board，轉錄與 review 綁同 capture；清理義務在父項刪除後保留原 SET NULL，usage 保留原無 FK 的歷史 UUID。金額為原 bigint 微元，numeric／JSON／timestamp 精度不經 JS number 轉換；本 migration 不啟用錄音 worker 或付費 provider。
- `0027`／`0028` 將會議內六個 task／producer-run／review／projection 引用改為 NO ACTION DEFERRABLE INITIALLY DEFERRED，於 transaction commit 核對；多層 Board／record cascade 可原子完成，仍有引用的獨立 task／run／capture 刪除不可提交。其他 FK／唯一約束、RLS／grants 及 cleanup SET NULL 不變。
- `0029` 提供 meeting editor／private-record 範圍內的 capture 讀取與受控 mutation。record／capture scope 只由交易核心重新授權後設定；取消以同一 invoker 交易處理 capture、run、cleanup obligation 與未送出的預留款。退款必須同時有 reserved、明確 pending 與 cancelled-before-dispatch；running、failed_retryable、unknown 或 legacy NULL 不退款，預算失衡整筆回滾。新增 nullable storage backend／dispatch state 不猜配或回填來源；沒有啟用付費 worker、全域 ledger API 或實際物件刪除。`0030` 僅保留 NULL node_type 的既有一般任務 pointer 語意，group／archived／異 Board 仍拒絕。
- `0031` 只開 editor／exact segment audio purpose 的 reservation／claim／verify 與既有 cleanup proof；server-held 隨機 operation token 可在原 actor／capture 已失效或刪除後，獨立清算自己的 GCS generation／outcome，不能修改業務 segment 或 global ledger。Unknown／pending 不重送 storage POST，不因 timeout 假報 quiescent。Stop anchor 同交易維護 cleanup due，不早於七天保留期／upload deadline；既有 NULL backend 不猜配。仍未啟用實際 purge 或新增 foundation role。
- `0032` 僅在 exact actor／record／capture 完成目的中核對已 verified 音訊、凍結來源並原子建立 source-vN run 與首筆 pending 預留；budget 只允許目前 server 月份 default INSERT／固定增額，不開一般 ledger API。重播不重留款，不足回 awaiting_budget，不完整來源不建 run；既有 cancel 退款與未知用量不變。provider／model／price 標記沿舊來源，並非真 provider 資格，沒有啟用 worker 或呼叫 provider。
- `0033` 只允許 exact current-source resolution 的人工 decisions 與 exact record／capture 的草稿 projection；原私人 editor 讀取不放寬，不開 transcript／worker／ledger 寫入。Resolution／review CAS、record 精確時間 CAS 與 projection request-key replay 由同一 actor transaction 驗證；只授 human match 欄位及 projection bookkeeping，不准改 transcript／候選語意分數或來源。取消／過期 resolution 不可決策。
- `0034`僅將run綁到原main AppSession的context，不複製cookie／bearer、不延長Session、不授ASR dispatch或transcript INSERT。綁定限目前actor／private-record editor、完整凍結來源、未到期queued／awaiting-budget run與相同Session；不可重綁其他context。背景僅依exact run讀回既有Session proof，再沿原Principal／mapping／guard／revoke／expiry驗證；context讀取不建立business actor。Session實體刪除後仍保留不可重綁的context UUID，查無原Session即停止、不轉綁其他Session；新欄位來源匯入維持NULL，不替歷史run猜配登入身分。
- `0035`在目前main Session與完整GCS來源下，將可證未送出的舊固定預留改為Cloud Speech時長／1秒進位／兩attempt成本池；不提高月額、不授派送或transcript寫入。NULL／dispatched或已有處理進度的legacy不得退款／覆寫。全部run／usage／budget變動採單交易，replay不重留款，pool INSERT失敗全部rollback。新欄位grants不擴大原cancel路徑；既有cancel／Session guard維持其他phase的必要保護。
- `0036`沿既有run領取一個ASR unit，150秒lease與server-only operation token綁定同一attempt；cost pool分配到unit不再增加月預留。同token重播不另領／留款，不同token不能接管未到期unit。Dispatch須重驗原main Session、權限、source version／GCS proof、lease、deadline與預留月份，僅保存固定sample／offset／digest metadata；未授transcript寫入或正式provider啟用。舊prepare／cancel路徑不得利用新欄位grants改寫ASR token、manifest或allocation。
- `0037`只在原Session、目前actor與source／lease有效時新增私有ASR unit checkpoint；50秒傳輸單元不是最終discussion，ASR完只移至retrieve，不造空候選、不切active revision或宣稱analysis ready。Checkpoint FORCE RLS、append-only runtime INSERT／SELECT，父capture／run／source刪除時cascade；不授importer假快照映射。Accounting-only按exact operation token結算自己的unit與未分配pool餘額，不重複退款、不覆寫未知收據，不得存私人結果；新spent／resume等欄位grants受精確guard約束，舊取消只退pool剩餘額。與既有actor kernel共用app transaction lock，run policy不反查usage造成RLS遞迴。Dispatch未知commit只讀回同payload，拒絕後不可再送；最後chunk須符合來源時長上下界。背景actor已失效時不寫capture，現行合法owner的status才可同步terminal run狀態。
- Managed連線由各lifecycle IAM login登入，server／Job先驗SESSION_USER與隔離membership，再進固定app role；LOGIN identity與current_user role分開驗證，以保留0029／0031／0032的guard。App role在managed foundation為NOLOGIN，不對它授DB CONNECT；CONNECT只給精確IAM login。Source適配不建立IAM user／grant、不改既有SQL，也不代表正式proxy或私網路徑已驗證。
- migration 必須可重複核對 checksum；相同版本及 bytes 只能 no-op，版本／checksum 漂移、缺號或未知檔案必須拒絕。禁止 down migration 與修改既有 SQL。

既有 migration 已將四個專用角色 ID 固定為 `_disposable` 後綴。為維持 checksum 與 forward-only 原則，managed profile 仍沿用這些 app 專用角色 ID；後綴是歷史名稱，不代表可繞過 managed binding。若未來更名，須新增 migration 完成 ownership／grant／policy 轉移，不得改寫 `0001`～`0014`。

## SQL 邊界

- 物件只能落在 `projed_core`／`projed_contract`，且需符合本次 source-controlled DEV-139 profile 的 allowlist。
- 所有 helper 必須是 `SECURITY INVOKER`、固定 `search_path` 並使用完整 schema 名稱；不得讀 `auth.users`、`auth.uid()` 或客戶端可傳入的 actor 參數。
- 新物件需明確撤銷 PUBLIC 權限；含使用者／資源資料的 table 須啟用並 FORCE RLS。不得建立跨 core FK、extension、任意 dynamic SQL 或 `SECURITY DEFINER`。
- 變更採 forward-only；runtime 啟動不自動 migrate、不修 grants、不以 checker 通過為由修改既有 shared foundation ACL。

靜態 checker 只檢查 source／SQL 形狀，不能取代 disposable PostgreSQL catalog、RLS、pool cleanup 或 HTTP verifier。
